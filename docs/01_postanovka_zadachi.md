## Предметная область

Группа из N подвижных объектов (узлов сети) перемещается в трёхмерном пространстве. У каждого узла есть два независимых источника информации о своём положении:

1. **Навигационная оценка** — аналог связки спутниковой навигации и инерциальной системы (ГНСС + ИНС). Оценка известна каждому узлу с некоторой погрешностью и со временем накапливает ошибку: в отсутствие внешней коррекции точность деградирует.
2. **Дальномерные измерения** — узлы умеют измерять расстояния друг до друга с некоторой настраиваемой погрешностью. Дальность — величина относительная: она ничего не говорит об абсолютном положении узла в пространстве, только о взаимном расположении пары узлов.

Требуется построить систему, которая, используя только эти два источника, восстанавливает координаты всех узлов сети как можно точнее — компенсируя дрейф навигации за счёт точной относительной геометрии, задаваемой дальномерами.

## Ключевая сложность задачи

Дальности между узлами не меняются при повороте или сдвиге всей группы как единого целого — расстояние между двумя точками инвариантно относительно общих трансляций и вращений системы. Из этого следует: **по одним лишь дальностям сеть восстанавливается только с точностью до неизвестного сдвига и поворота**.

Практическое следствие: алгоритм оптимизации, минимизирующий только невязки дальностей, может найти геометрически идеальную форму сети, «подвешенную» в произвольном месте и с произвольной ориентацией — то есть корректную по форме, но бесполезную как абсолютная локализация.

Неоднозначность устраняется одним из двух способов:

- **Опорные узлы (анкеры)** — несколько узлов с точно известными координатами, зафиксированными и не участвующими в оптимизации. Они физически фиксируют систему отсчёта.
- **Привязка к навигационным оценкам** — если анкеров нет, система отсчёта наследуется от исходных (пусть и неточных) навигационных данных самих узлов через жёсткое совмещение (без анкеров это единственный источник абсолютной привязки).

## Требования к решению

1. **Модель мира**: генерация случайной сети из N узлов в кубе заданного размера, с настраиваемой ошибкой навигации и ошибкой дальномеров.
2. **Топология измерений**: каждый узел не обязан измерять расстояние до всех остальных — достаточно k ближайших целей.
3. **Алгоритм локализации**: два источника информации (дальности и навигация) должны объединяться статистически корректно — с весами, обратно пропорциональными дисперсии каждого источника, без ручного подбора коэффициентов под конкретный сценарий.
4. **Временная динамика**: узлы физически перемещаются, навигационная ошибка продолжает расти, дальности пересчитываются — система должна непрерывно переоценивать положение на каждом шаге времени, а не решать задачу однократно.
5. **Устойчивость**: алгоритм не должен расходиться (nan, бесконечности) независимо от масштаба сцены — от помещения размером 2×2×2 м до полигона 50×50×50 км.
6. **Оцениваемость результата**: система должна выдавать количественные метрики качества локализации, сравнимые между разными сценариями и разными моментами времени.

## критерии проверки решения

Задача считается решённой, если для набора контрольных сценариев (нормальная навигация и дальномеры; сильно зашумлённая навигация; сильно зашумлённые дальномеры; предельно малый и предельно большой масштаб сцены; плотная сеть; сценарии с 1–3 анкерами) система:

- не расходится (отсутствуют nan/inf в решении);
- после коррекции ошибка положения (rmse) ниже ошибки чистого навигационного дрейфа;
- для сценариев с анкерами абсолютная ошибка контролируема и не растёт неограниченно во времени.
