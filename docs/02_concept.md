# Концептуальное описание решения

## Общая идея

Решение реализовано как двухступенчатый оптимизационный конвейер, выполняемый однократно перед началом движения (статическая коррекция) и затем повторяемый на каждом шаге временной динамики (тик):

```
k-NN топология измерений  →  Градиентный спуск (грубая оценка)  →  EKF (точная рекурсивная оценка)  →  Фиксация системы отсчёта (Кабш / анкеры)
```

Каждый узел сети хранит четыре разные координаты одновременно — в этом центральная идея модели мира:

| Поле узла | Смысл |
|---|---|
| `RealCoord` | Истинное положение. Недоступно алгоритмам, служит только эталоном для расчёта метрик качества. |
| `BelievedCoord` | Навигационная оценка узла (ГНСС+ИНС). Смещена от истины шумом, дальше дрейфует со временем. |
| `InitialCoord` | Точка регуляризации для градиентного спуска. Обновляется значением `BelievedCoord` перед каждым шагом оптимизации. |
| `CurrentCoord` | Рабочая оценка алгоритмов — итоговый выход системы. |

Анкеры (первые `anchors_count` узлов) — частный случай: у них все четыре координаты всегда равны истинной, `Uncertainty = 0`, и они полностью исключены из оптимизации (не двигаются градиентным спуском, не входят в вектор состояния EKF).

## Топология измерений: асимметричный k-NN

Полносвязная сеть (каждый узел измеряет расстояние до каждого) не масштабируется на большие N. Вместо этого каждый подвижный узел строит список из k ближайших целей **по собственным измерениям** — то есть топология направленная и несимметричная: измерение «от узла i к узлу j» существует независимо от обратного измерения «от j к i». Если вокруг узла B есть плотное скопление, узлы этого скопления выберут B соседом, но B не обязательно выберет их — направленность отражает реальную асимметрию плотности сети.

Анкеры не инициируют измерений (не могут быть источником `From`), но могут быть целью измерения (`To`) — они пассивные ориентиры, а не участники локализационной задачи.

## Ступень 1: градиентный спуск — грубая сборка геометрии

Минимизируется функция стоимости из двух слагаемых:

1. **Невязки дальностей** — модель, аналогичная системе пружин: каждое измерение стягивает или расталкивает пару узлов, пока вычисленное расстояние не совпадёт с измеренным. Каждое измерение двигает оба своих конца (симметризация на уровне градиента, даже если сам список измерений асимметричен).
2. **Байесовская привязка к навигационной точке** `InitialCoord` — вес привязки не фиксирован, а вычисляется из отношения дисперсий двух источников: `distErr² / Uncertainty²`. Пока навигация точна (узел только что стартовал, `Uncertainty` мало), узел жёстко удерживается около своей навигационной оценки; по мере дрейфа вес автоматически падает, и приоритет переходит к дальномерам. Это устраняет ручной подбор коэффициента регуляризации под конкретный сценарий.

Устойчивость обеспечивается тем, что перед каждым шагом делается снимок координат; если шаг привёл к росту стоимости или к NaN/Inf — координаты откатываются, а длина шага уменьшается вдвое; после удачного шага длина шага постепенно восстанавливается. Это единственный механизм, который позволяет одному и тому же алгоритму работать без ручной перенастройки шага и на сцене 2×2×2 метра, и на сцене 50×50×50 километров.

## Ступень 2: расширенный фильтр Калмана (EKF) — точное рекурсивное уточнение

Вектор состояния фильтра — координаты только подвижных узлов; анкеры в состояние не входят и участвуют в вычислениях как константы.

Вектор измерений — составной, оба источника информации объединены в одном фильтре:

1. Дальномерные измерения (шум одинаковый для всех, параметр `r`).
2. Псевдо-GPS измерения: навигационная оценка `BelievedCoord` каждого подвижного узла подаётся как прямое наблюдение его координат с индивидуальной дисперсией `Uncertainty²`.

Ковариационная матрица `P` **персистентна между тиками** — передаётся из вызова в вызов (инициализируется единичной матрицей только при самом первом вызове). Накопленная уверенность в оценке не сбрасывается на каждом шаге времени, а нарастание неопределённости между тиками моделируется добавкой шума процесса `Q` на этапе предсказания.

## Фиксация системы отсчёта: алгоритм Кабша

Когда анкеров нет, дальности не определяют абсолютный сдвиг и поворот сети целиком (см. «Постановку задачи»). После оптимизации решение жёстко совмещается с опорным набором координат алгоритмом Кабша: находится оптимальный поворот и сдвиг (без масштабирования), минимизирующий сумму квадратов расстояний между соответствующими точками. Поворот вычисляется через сингулярное разложение (SVD) ковариационной матрицы центрированных координат; отражение исключается поправкой знака определителя.

Опорный набор для совмещения выбирается по-разному в двух ситуациях:

- при начальной (статической) коррекции — навигационные оценки `BelievedCoord` (система отсчёта наследуется от исходной, пусть и неточной, спутниковой привязки);
- на каждом шаге времени — снимок `CurrentCoord` сразу после переноса по командной скорости движения, но до переоптимизации (то есть результат счисления пути).

Таким образом, оптимизатор улучшает только форму сети, а абсолютная система отсчёта передаётся по цепочке счисления пути от исходной привязки. При наличии анкеров совмещение по Кабшу не выполняется — привязку и без того обеспечивают сами анкеры.

## Модель роста навигационной ошибки

Неопределённость подвижного узла растёт не линейно, а квадратично: `e(t) = e₀ + k·t²`. Обоснование физическое: инерциальные датчики измеряют ускорение, а не координату напрямую; чтобы ошибка ускорения перешла в ошибку координаты, её нужно проинтегрировать дважды. Отсюда в момент старта (t = 0) скорость роста ошибки равна нулю, и линейная модель `e(t) = e₀ + k·t` физически не обоснована — она заставляла бы алгоритм компенсировать завышенную ошибку с первых же шагов. Подробное обоснование с формулами и сравнительной таблицей — см. исходную заметку [`legacy/error_growth_model.md`](legacy/error_growth_model.md).

Приращение неопределённости за один шаг времени — `k·(2t−1)` (телескопическая сумма даёт квадратичный закон); на ту же величину случайно размывается `BelievedCoord`.

## Временной цикл

1. Движение роя: все узлы сдвигаются по общему командному вектору скорости. `RealCoord` — истинное исполнение команды; `BelievedCoord` и `CurrentCoord` сдвигаются на ту же величину. Анкеры знают своё положение точно в любой момент.
2. Рост ошибки: неопределённость подвижных узлов растёт по квадратичному закону, навигационные оценки размываются.
3. Перенос `BelievedCoord` в `InitialCoord` — свежая точка регуляризации для очередного цикла градиентного спуска.
4. Пересчёт матрицы дальностей по новым истинным положениям.
5. Переоптимизация с продолжением от текущей оценки: короткий градиентный спуск, затем EKF с унаследованной ковариацией; без анкеров — совмещение по Кабшу с предсказанными координатами.
6. Расчёт и запись метрик шага.

## Метрики качества

- **RawRMSE** — ошибка навигационных оценок `BelievedCoord` относительно истины: чистый дрейф без какой-либо коррекции.
- **FinalRMSE** — ошибка итоговых оценок `CurrentCoord` после работы обеих ступеней алгоритма.
- **ShapeRMSE** — ошибка `CurrentCoord` после дополнительного оптимального совмещения с истиной по Кабшу: чистое качество восстановленной геометрии сети, без учёта ошибки абсолютной привязки.
- **CompensationRatio** = RawRMSE / FinalRMSE — во сколько раз взаимные дальномерные измерения снизили ошибку по сравнению с необработанным навигационным дрейфом.
