# Восток — кооперативная локализация подвижной сенсорной сети в трёхмерном пространстве

## Постановка задачи

Группа из N подвижных объектов (узлов сети) перемещается в пространстве. Каждый узел знает своё положение лишь приближённо: оценка спутниковой и инерциальной навигации со временем накапливает ошибку (дрейф). При этом узлы умеют точно измерять расстояния друг до друга дальномерами.

Программа моделирует процесс, в котором точная относительная геометрия (взаимные дальности) непрерывно исправляет накапливающуюся абсолютную ошибку положения. Ключевая сложность: расстояния не зависят от сдвига и поворота всей группы как целого, поэтому по одним лишь дальностям сеть можно восстановить только «с точностью до положения в пространстве». Эта неоднозначность устраняется либо опорными узлами с точно известными координатами, либо привязкой к навигационным оценкам самих узлов.

## Структура проекта

```
cmd/main.go            — запуск, разбор параметров, временной цикл, итоговые метрики
config/*.toml          — сценарии: без опорных узлов (базовый, плохая навигация,
                         плохие дальномеры, малый и большой масштаб, плотная сеть)
                         и с одним, двумя и тремя опорными узлами
pkg/types/             — структуры данных: узел, точка, скорость, измерение, конфигурация
pkg/environ/           — генерация мира и модель движения с ростом ошибки
pkg/algorithms/        — градиентный спуск, расширенный фильтр Калмана,
                         выбор ближайших соседей, алгоритм Кабша
pkg/analytics/         — расчёт и вывод метрик, анализ истории фильтра
pkg/io/                — чтение конфигурации, запись журналов в CSV
testbench.py           — интерактивный испытательный стенд с графиками и отчётом
```

## Модель мира

Узлы размещаются случайно в кубе [sMin, sMax]³. Каждый узел хранит четыре координаты:

- `RealCoord` — истинное положение (недоступно алгоритмам, служит эталоном для метрик);
- `BelievedCoord` — навигационная оценка узла; при создании смещена от истины равномерным шумом ±gpsErr, далее дрейфует;
- `InitialCoord` — точка привязки для регуляризации градиентного спуска; на каждом шаге времени обновляется значением `BelievedCoord`;
- `CurrentCoord` — рабочая оценка алгоритмов, итог работы системы.

Первые `anchors_count` узлов — опорные: их координаты точны, неопределённость нулевая, в оптимизации они не участвуют и служат неподвижными ориентирами.

Дальномерные измерения — симметричная матрица попарных расстояний: истинное расстояние плюс равномерный шум ±distErr. Матрица пересчитывается на каждом шаге времени по новым истинным положениям.

Модель дрейфа: неопределённость узла растёт по квадратичному закону e(t) = e₀ + k·t² (двойное интегрирование ошибки ускорения в инерциальной навигации). За один шаг времени неопределённость увеличивается на k·(2t−1), и на эту же величину случайно размывается `BelievedCoord`.

## Топология измерений

Каждый подвижный узел измеряет расстояния до k ближайших целей (по текущей матрице расстояний). Список измерений направленный и несимметричный: измерение «от узла i к узлу j» существует независимо от обратного. Опорные узлы измерений не инициируют, но могут быть целями.

Функция проверки связности обходит направленный граф измерений в ширину и предупреждает, если от какого-либо подвижного узла нет пути до опорного — тогда его положение по дальностям не привязывается к абсолютным координатам.

Значение k задаётся флагом командной строки или конфигурацией; по умолчанию k = N−1 (полносвязная сеть).

## Ядерные алгоритмы

Оценка положения двухступенчатая: сначала градиентный спуск грубо собирает геометрию сети, затем расширенный фильтр Калмана уточняет её с учётом статистических весов всех источников.

### Ступень 1. Градиентный спуск (pkg/algorithms/gradient.go)

Минимизируется функция стоимости из двух слагаемых:

1. Сумма квадратов невязок дальностей: для каждого измерения — квадрат разности между расстоянием, вычисленным по текущим оценкам координат, и измеренным значением. Модель аналогична системе пружин: каждое измерение «стягивает» или «расталкивает» пару узлов. Градиент по узлу пропорционален вектору направления на соседа с множителем (1 − d_изм/d_выч); каждое измерение двигает оба своих конца.
2. Квадратичная привязка каждого подвижного узла к точке `InitialCoord`. Вес привязки статистический: отношение дисперсий источников distErr²/Uncertainty², индивидуально для каждого узла. Пока навигация точна (малая неопределённость), узел удерживается около своей навигационной оценки; по мере дрейфа вес автоматически затухает и дальномеры получают приоритет. Ручной подбор коэффициента регуляризации не требуется.

Защита от расходимости — откат неудачного шага: если после шага стоимость выросла либо стала нечисловой, координаты возвращаются к снимку до шага, а длина шага уменьшается вдвое; после удачного шага длина постепенно восстанавливается (умножение на 1,1, но не выше исходной). Это снимает зависимость длины шага от масштаба сцены — от комнаты в два метра до разноса в пятьдесят километров.

Остановка: максимальное смещение узла за итерацию меньше порога eps, исчерпание лимита итераций либо вырождение шага.

Опорные узлы в градиентном спуске неподвижны: их градиенты не накапливаются и координаты не обновляются.

### Ступень 2. Расширенный фильтр Калмана (pkg/algorithms/ekf.go)

Вектор состояния — координаты только подвижных узлов (по три компоненты на узел); опорные узлы исключены из состояния и участвуют в вычислениях как константы.

Вектор измерений составной:

1. Дальности из списка измерений; дисперсия шума r одинакова для всех.
2. Псевдонавигационные измерения: `BelievedCoord` каждого подвижного узла как прямое наблюдение его координат с дисперсией Uncertainty². Благодаря этому объединение относительной геометрии (дальностей) и абсолютной привязки (навигации) происходит внутри одного фильтра с корректными статистическими весами: чем сильнее дрейф узла, тем меньше фильтр доверяет его навигационной оценке.

Матрица чувствительности измерений (якобиан): для дальности между узлами i и j — единичный вектор направления между их текущими оценками, записанный с противоположными знаками в блоки обоих узлов (для опорного узла блок отсутствует); для псевдонавигационных измерений — единичные элементы на соответствующих компонентах состояния.

Итерация фильтра стандартная:

- предсказание: P = P + Q (Q — диагональная матрица шума процесса);
- невязка: Y = Z − Z_выч, где Z_выч пересчитывается по текущему состоянию, включая линеаризацию дальностей;
- ковариация невязки: S = H·P·Hᵀ + R;
- коэффициент усиления: K = P·Hᵀ·S⁻¹;
- коррекция: X = X + K·Y; P = (I − K·H)·P.

Ковариационная матрица P сохраняется между шагами времени (передаётся из вызова в вызов; при первом вызове инициализируется единичной). Фильтр работает как подлинно рекурсивный: накопленная уверенность в координатах не сбрасывается, а нарастание неопределённости между шагами моделируется добавкой Q на этапе предсказания.

### Фиксация системы отсчёта. Алгоритм Кабша (pkg/algorithms/kabsch.go)

Когда опорных узлов нет, дальности не определяют сдвиг и поворот группы: оптимизатор может незаметно смещать и вращать весь каркас сети, не меняя стоимость. Для устранения этой неоднозначности после оптимизации решение жёстко совмещается с опорным набором координат алгоритмом Кабша: находится оптимальный поворот и сдвиг (без масштабирования), минимизирующие сумму квадратов расстояний между парами точек. Поворот вычисляется через сингулярное разложение ковариационной матрицы центрированных наборов; отражение исключается поправкой знака определителя.

Опорный набор выбирается так:

- при начальной оптимизации — навигационные оценки `BelievedCoord` (система отсчёта наследуется от спутниковой привязки);
- на каждом шаге времени — снимок оценок `CurrentCoord` после переноса по командной скорости, но до оптимизации (счисление пути).

В результате оптимизация улучшает только форму сети, а система отсчёта передаётся по цепочке счисления от начальной привязки. При наличии опорных узлов совмещение не выполняется — привязку обеспечивают сами опорные узлы.

## Временной цикл (cmd/main.go)

Перед циклом выполняется начальная оптимизация: полный градиентный спуск (до max_iter итераций), затем расширенный фильтр Калмана (ekf_iter итераций); без опорных узлов — совмещение с навигационными оценками.

Далее выполняется заданное число шагов времени, на каждом:

1. Перемещение группы: все узлы сдвигаются по общему командному вектору скорости. `RealCoord` — истинное исполнение команды; `BelievedCoord` и `CurrentCoord` сдвигаются на ту же величину (счисление пути по известной команде). Опорные узлы знают своё положение точно.
2. Рост ошибки: неопределённость подвижных узлов увеличивается по квадратичному закону, навигационные оценки размываются.
3. Перенос `BelievedCoord` в `InitialCoord` — свежая точка привязки для регуляризации.
4. Пересчёт матрицы дальностей по новым истинным положениям.
5. Переоптимизация с продолжением от текущей оценки: короткий градиентный спуск, затем фильтр Калмана с унаследованной ковариацией; без опорных узлов — совмещение по Кабшу с предсказанными координатами.
6. Расчёт и запись метрик шага.

Параметры цикла задаются в секции `[dynamics]` конфигурации (или одноимёнными флагами командной строки): число шагов `ticks`, длительность шага `dt`, скорость группы `swarm_speed`, коэффициент роста ошибки `growth_rate`, итерации на шаг `gd_iters_per_tick` и `ekf_iters_per_tick`.

## Метрики

Все метрики — среднеквадратичная ошибка по подвижным узлам относительно истинных координат:

- **RawRMSE** — ошибка навигационных оценок `BelievedCoord`: дрейф без какой-либо коррекции;
- **FinalRMSE** — ошибка итоговых оценок `CurrentCoord` после работы алгоритмов;
- **ShapeRMSE** — ошибка после оптимального совмещения итоговых оценок с истиной по Кабшу: чистое качество геометрии сети, без ошибки абсолютной привязки;
- **CompensationRatio** = RawRMSE / FinalRMSE — во сколько раз взаимные замеры уменьшили ошибку по сравнению с чистым дрейфом.

## Запуск

```
go run ./cmd/main.go -config config/00_base.toml
go run ./cmd/main.go -nodes 8 -gps-err 5 -dist-err 0.3 -anchors 2 -k 4 -ticks 5
```

При флаге `-config` все параметры, включая секцию `[dynamics]`, берутся из TOML-файла; флаг `-k` имеет приоритет над конфигурацией. Минимум три узла.

Выходные файлы в корне проекта (журналы алгоритмов накапливаются по всем шагам времени):

- `mod1_history.csv` — траектория первого подвижного узла в градиентном спуске;
- `ekf_history.csv` — состояние всех подвижных узлов по итерациям фильтра Калмана;
- `tick_history.csv` — метрики по шагам времени.

Испытательный стенд `python3 testbench.py`: прогон одного сценария или пакетный прогон всех, графики сходимости и динамики в `report_images/`, накопительный отчёт `report.md`.

## Известные ограничения

- Шумы фильтра Калмана `q` и `r` подбираются под сценарий вручную (рекомендация: r ≈ dist_err²).
