# Структура проекта

## Дерево каталогов

```
vostok/
├── go.mod, go.sum            — модуль "vostok", Go 1.26.4
├── README.md                 — краткая документация (постановка задачи, алгоритмы, запуск)
├── cmd/
│   └── main.go                — точка входа: CLI/TOML-конфигурация, статическая коррекция,
│                                 временной цикл, печать и запись метрик
├── config/                    — 10 сценариев запуска (TOML), см. таблицу ниже
├── docs/                      — документация проекта (этот комплект файлов)
├── pkg/
│   ├── types/types.go          — структуры данных: Config, Node, Point, Velocity, Measurement
│   ├── environ/
│   │   ├── env.go              — генерация случайного мира, матрица дальностей
│   │   └── kinematics.go        — движение роя, квадратичный рост навигационной ошибки
│   ├── algorithms/
│   │   ├── gradient.go          — градиентный спуск с откатом неудачного шага
│   │   ├── ekf.go                — расширенный фильтр Калмана
│   │   ├── kabsch.go             — алгоритм Кабша (фиксация системы отсчёта)
│   │   └── k-nearest.go          — построение k-NN измерений, проверка связности
│   ├── analytics/metrics.go     — RMSE/дисперсия, анализ истории EKF
│   └── io/io.go                  — чтение TOML-конфигурации, запись CSV-журналов
└── testbench.py                — интерактивный испытательный стенд (запуск, графики, отчёт)
```

Выходные файлы:

- `mod1_history.csv` — траектория первого подвижного узла в градиентном спуске (накапливается по всем тикам);
- `ekf_history.csv` — состояние всех подвижных узлов по итерациям EKF (накапливается по всем тикам);
- `tick_history.csv` — метрики по шагам времени (перезаписывается целиком при каждом запуске);
- `report.md`, `report_images/*.png` — накопительный журнал прогонов `testbench.py` с графиками.

## Поток данных между модулями

```
TOML-конфиг / CLI-флаги
        │
        ▼
  io.LoadConfigFromFile ──► types.Config
        │
        ▼
  environ.BuildMap ──► []*types.Node, []types.Point (RealCoord), [][]float64 (расстояния)
        │
        ▼
  algorithms.BuildMeasurements(nodes, distances, k) ──► []types.Measurement
        │
        ├──► algorithms.CheckConnectivity (диагностика, только если anchors_count > 0)
        │
        ▼
  algorithms.RunGradientDescent(nodes, measurements, ...) ──► обновляет Node.CurrentCoord
        │                                                      + пишет mod1_history.csv
        ▼
  algorithms.RunEKF(nodes, measurements, ..., P) ──► обновляет Node.CurrentCoord, возвращает P
        │                                             + пишет ekf_history.csv
        ▼
  algorithms.AlignMovableToReference (только если anchors_count == 0, алгоритм Кабша)
        │
        ▼
  analytics.ComputeGlobalMetrics / SummarizeEKFSpread ──► RMSE, дисперсия
        │
        ▼
  cmd/main.go: печать метрик тика, запись tick_history.csv
        │
        │  (цикл повторяется на каждом тике: environ.StepSwarmMotion →
        │   environ.GrowUncertainty → environ.RefreshInitialCoord →
        │   environ.RecomputeDistances → снова BuildMeasurements → GD → EKF → Kabsch)
        ▼
testbench.py: subprocess.run("go run ./cmd/main.go -config ...") ──► pandas читает CSV
        │
        ▼
matplotlib строит графики (report_images/*.png) ──► report.md (журнал прогонов)
```

## Назначение файлов пакетов

### `pkg/types/types.go`

Центральные структуры данных всего проекта:

- `Config` — маппинг TOML-конфигурации (секции `network`, `hyperparams`, `topology`, `dynamics`).
- `Node` — узел сети: `ID`, четыре координаты (`InitialCoord`, `CurrentCoord`, `RealCoord`, `BelievedCoord`), `Uncertainty`, `TickCounter`, `IsAnchor`.
- `Point{X, Y, Z}`, `Velocity{X, Y, Z}` — векторные величины.
- `Measurement{From, To, Value}` — направленное дальномерное измерение.
- `Distance(p1, p2 Point) float64` — евклидово расстояние.

### `pkg/environ/env.go`

Генерация мира:

- `BuildMap` — создаёт N узлов со случайными истинными координатами в кубе `[sMin, sMax]³`; первые `anchorsCount` узлов — точные анкеры; остальные получают зашумлённую навигационную оценку. Строит начальную матрицу дальностей.
- `RecomputeDistances` — пересчитывает матрицу дальностей по текущим `RealCoord` (вызывается на каждом тике).
- `buildDistanceMatrix` — внутренняя функция: симметричная матрица истинных расстояний + равномерный шум, с защитой от отрицательных значений.

### `pkg/environ/kinematics.go`

Модель движения и роста ошибки:

- `NodeMovement` — сдвигает `RealCoord` узла по вектору скорости.
- `ErrorShift` — квадратичный рост неопределённости узла, размытие `BelievedCoord`. Пропускает анкеров.
- `StepSwarmMotion` — двигает весь рой: истинное исполнение команды (`RealCoord`) и счисление пути (`BelievedCoord`, `CurrentCoord`); анкеры синхронизируют все поля с `RealCoord`.
- `GrowUncertainty` — применяет `ErrorShift` ко всем узлам.
- `RefreshInitialCoord` — переносит `BelievedCoord` в `InitialCoord` (новая точка регуляризации для очередного цикла градиентного спуска).

### `pkg/algorithms/gradient.go`

`RunGradientDescent` — Ступень 1 локализации (см. [02_concept.md](02_concept.md)): минимизация суммы невязок дальностей и байесовски взвешенной привязки к `InitialCoord`, с защитой от расходимости через откат неудачного шага. Логирует траекторию первого подвижного узла в CSV. Возвращает номер итерации, на которой остановился.

### `pkg/algorithms/ekf.go`

`RunEKF` — Ступень 2 локализации: расширенный фильтр Калмана с составным вектором измерений (дальности + псевдо-GPS), персистентной ковариацией между тиками. Логирует состояние всех подвижных узлов по итерациям. Возвращает обновлённую ковариационную матрицу `P` для передачи в следующий тик.

### `pkg/algorithms/kabsch.go`

- `KabschAlign` — классический алгоритм Кабша: оптимальное совмещение двух наборов точек поворотом и сдвигом через SVD ковариационной матрицы, с коррекцией знака детерминанта против отражения.
- `AlignMovableToReference` — применяет `KabschAlign` только к подвижным узлам, результат записывает обратно в `CurrentCoord`.

### `pkg/algorithms/k-nearest.go`

- `BuildMeasurements` — строит направленный несимметричный список измерений: для каждого подвижного узла — k ближайших целей по текущей матрице расстояний.
- `CheckConnectivity` — обход в ширину направленного графа измерений; предупреждает, если от какого-либо подвижного узла нет пути до анкера.

### `pkg/analytics/metrics.go`

- `ComputeGlobalMetrics` — RMSE координатных оценок относительно истины и дисперсия невязок дальностей внутри текущей геометрии.
- `SummarizeEKFSpread` — читает `ekf_history.csv`, возвращает размах (max−min) координат по итерациям как индикатор сходимости фильтра.

### `pkg/io/io.go`

- `LoadConfigFromFile` — чтение и разбор TOML-конфигурации.
- `WriteHistoryToCSV` — универсальная запись CSV-журнала (используется градиентным спуском), с поддержкой дозаписи между тиками.
- `SaveEKFHistory` — специализированная запись журнала EKF с фиксированным форматом заголовка и точности.

### `cmd/main.go`

Точка входа: разбор CLI-флагов и/или TOML-конфигурации, построение мира, статическая коррекция, затем цикл по тикам временной динамики, печать и сохранение метрик. Подробный алгоритм — см. [05_algorithms.md](05_algorithms.md).

### `testbench.py`

Интерактивный испытательный Python-стенд (pandas + matplotlib). Не содержит собственной вычислительной логики симуляции — оркестрирует Go-бинарник (`go run ./cmd/main.go -config ...`), парсит сгенерированные им CSV через pandas, строит графики сходимости через matplotlib, ведёт накопительный markdown-журнал прогонов с привязкой к git-коммиту. Режимы: запуск одного сценария, пакетный прогон всех сценариев из `config/`.

## Сценарии `config/*.toml`

Все файлы имеют одинаковую структуру секций: `[network]` (число узлов, границы пространства, ошибка навигации, ошибка дальномеров), `[hyperparams]` (параметры GD и EKF), `[topology]` (k), `[dynamics]` (параметры временного цикла).

| Файл | Сценарий | Что проверяет |
|---|---|---|
| `00_base.toml` | Базовый | Эталонное поведение при хорошей навигации (gps_err=0.5) и точных дальномерах (dist_err=0.02) |
| `01_bad-gps.toml` | Плохая навигация | Восстановление при огромной начальной ошибке навигации (gps_err=45) на фоне точных дальномеров |
| `02_bad-sensors.toml` | Плохие дальномеры | Байесовское взвешивание при недостоверных дальностях (dist_err=12) — коррекция не должна портить оценку |
| `03_edge-micro.toml` | Малый масштаб | Устойчивость на сцене 2×2×2 м — критическая чувствительность к длине шага GD |
| `04_edge-macro.toml` | Большой масштаб | Устойчивость на сцене 50×50×50 км — численная защита GD (откат неудачного шага) от переполнения/NaN |
| `05_dense.toml` | Плотная сеть | Стресс-тест производительности на 50 узлах |
| `06_anc1.toml` | 1 анкер | Работа гибридной привязки с минимальным числом опорных узлов |
| `07_anc2.toml` | 2 анкера | То же с двумя опорными узлами |
| `08_anc3.toml` | 3 анкера | Полная фиксация системы отсчёта анкерами (без Кабша) |
| `09_anc_bad-gps.toml` | Анкеры + плохая навигация | Комбинация анкеров с сильным навигационным шумом |

## Сборка и запуск

Модуль: `vostok`, Go 1.26.4. Зависимости: `github.com/pelletier/go-toml/v2` (парсинг TOML), `gonum.org/v1/gonum` (линейная алгебра: `mat.Dense`, `mat.VecDense`, `mat.SVD`).

```bash
go run ./cmd/main.go -config config/00_base.toml
go run ./cmd/main.go -nodes 8 -gps-err 5 -dist-err 0.3 -anchors 2 -k 4 -ticks 5
python3 testbench.py
```

При флаге `-config` все параметры (включая `[dynamics]`) берутся из TOML-файла; флаг `-k` имеет приоритет над конфигурацией. Минимум три узла.
