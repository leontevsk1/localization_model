# Заметка: устранение трёх дефектов коррекции координат

> Историческая заметка (план, полностью реализован). Описывает мотивацию трёх ключевых механизмов текущей системы: байесовское взвешивание в GD, откат неудачного шага, фиксацию системы отсчёта по Кабшу и персистентную ковариацию EKF. Итоговое поведение см. в [../02_concept.md](../02_concept.md), код — `pkg/algorithms/gradient.go`, `pkg/algorithms/kabsch.go`, `pkg/algorithms/ekf.go`.

## Обнаруженные дефекты

Анализ ранних прогонов регрессионных сценариев выявил три проблемы:

- **`02_bad-sensors`**: коррекция вредила (compensation ratio 0.58–0.87, то есть хуже чистого дрейфа) — градиентный спуск не взвешивал невязки относительно качества датчиков, и большая ошибка дальномеров (dist_err = 12 м) портила изначально неплохую навигационную оценку (σ = 3 м).
- **`04_edge-macro`**: NaN в решении — градиентный спуск расходился при большом шаге (alpha = 5.0, необходимом для масштаба сцены в 50 км), NaN не перехватывался и приводил к ложной «сходимости на итерации 0».
- **`01_bad-gps`**: плато итоговой ошибки на уровне ~26.5 м — форма сети была собрана дальномерами верно, но сдвиг и поворот всего каркаса (неоднозначность системы отсчёта) оставались неустранёнными.

## Решение 1 — статистическое взвешивание в градиентном спуске

Вместо фиксированного веса привязки к `InitialCoord` — веса, обратные дисперсиям источников: невязки дальностей получают вес `1/dist_err²`, привязка к навигационной точке — `1/Uncertainty_i²` индивидуально для каждого узла. Эффект: при `dist_err >> gps_err` коррекция дальномерами автоматически ослабляется (ratio не проваливается ниже 1), а по мере роста дрейфа вес привязки к навигации сам ослабевает со временем. Ручной подбор коэффициента регуляризации под сценарий больше не требуется.

## Решение 2 — фиксация системы отсчёта по Кабшу

После градиентного спуска и EKF, если анкеров нет, решение жёстко выравнивается по алгоритму Кабша к предсказанным координатам (снимок `CurrentCoord` после счисления пути, до оптимизации). Оптимизатор перестаёт вносить в решение произвольный сдвиг и поворот; система координат наследуется от исходной навигационной привязки. Ошибка формы сети (`ShapeRMSE`) отделяется от абсолютной ошибки привязки (которая остаётся чистым дрейфом счисления пути).

## Решение 3 — численная защита градиентного спуска

Откат неудачного шага: если после шага суммарная невязка выросла — шаг откатывается, длина шага уменьшается вдвое. Убирает необходимость вручную подбирать длину шага под масштаб сцены (0.0005 для комнаты в 2 метра, 5.0 для полигона в 50 км). Дополнительно — защита от NaN/Inf: при обнаружении — принудительный останов с сообщением, вместо тихой ложной «сходимости».

## Решение 4 — персистентная ковариация EKF

До исправления `RunEKF` каждый тик сбрасывал ковариацию `P = I` — фильтр «забывал» накопленную уверенность и заново одинаково доверял всем узлам при каждом вызове. Исправление: `P` хранится между тиками, на этапе предсказания добавляется шум процесса `Q`. Только после этого EKF стал настоящим рекурсивным фильтром, а не пакетным решателем, запускаемым заново на каждом шаге.

## Решение 5 — навигационная оценка как измерение EKF

В вектор измерений EKF добавлено псевдо-GPS-наблюдение: `z_i = BelievedCoord_i` с дисперсией `R = Uncertainty_i²`. Объединение относительной геометрии (дальностей) и абсолютной привязки (навигации) происходит в одном месте с корректными статистическими весами; градиентный спуск остаётся нужен только для грубого старта (cold start).

## Метрика для контроля результата

Итоговая ошибка (`FinalRMSE`) разделена на ошибку формы (`ShapeRMSE`, после совмещения с истиной по Кабшу) и ошибку абсолютной привязки (разница между `FinalRMSE` и `ShapeRMSE`). Без этого разделения улучшения по решениям 1–2 нельзя было бы измерить отдельно — обе составляющие ошибки были смешаны в одном числе.
